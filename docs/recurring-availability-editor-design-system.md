# Recurring Availability Editor

## Overview

The `RecurringAvailabilityEditor` component provides a friendly UI for configuring recurring availability rules using RRULE (iCalendar recurrence rule format). It includes a live preview of the next 5 occurrences and a human-readable summary generated by the `rrule` library's `toText()` method.

**Component location:** `src/components/dashboard/recurring-availability-editor.tsx`

## Features

- **Frequency Selection**: Choose between Daily, Weekly, or Monthly via a segmented radio group
- **Interval**: Set an interval (e.g., "Every 3 weeks") with a numeric input (1–52)
- **Weekday Multi-Select**: Toggle individual days of the week for Weekly/Monthly frequency using checkbox chips
- **End Condition**: Choose between Never, After N occurrences, or On a specific date
- **Live Preview**: Displays the next 5 upcoming dates based on the configured rule
- **Plain-Language Summary**: Auto-generated summary using `rrule.toText()` (e.g., "every week on Tuesday, Thursday, Saturday")
- **Live Region Announcements**: Screen reader announcements for frequency changes, weekday toggles, and end condition changes

## Accessibility (WCAG 2.1 AA)

### Keyboard Navigation

| Control | Interaction |
|---------|-------------|
| Frequency radio group | Arrow keys (left/right/up/down) to switch between options. Roving `tabIndex`: only the selected radio has `tabIndex="0"`. |
| Weekday checkbox chips | Click or Enter/Space to toggle. |
| End condition radio group | Arrow keys to switch between Never, After, On date. |
| Number inputs | Standard keyboard input for numeric values. |
| Date input | Native date picker with keyboard support. |

### ARIA Implementation

| Element | ARIA Attribute |
|---------|----------------|
| Frequency group | `role="radiogroup"`, `aria-labelledby` → legend |
| Each frequency option | `role="radio"`, `aria-checked` |
| Weekday group | `role="group"`, `aria-labelledby` → legend |
| Each weekday | `role="checkbox"`, `aria-checked` |
| End condition group | `role="radiogroup"`, `aria-labelledby` → legend |
| Each end option | `role="radio"`, `aria-checked` |
| Summary area | `aria-live="polite"`, `aria-atomic="true"` |
| Screen reader live region | `role="status"`, `aria-live="polite"`, `aria-atomic="true"` |
| Weekday validation | `role="alert"` when no days selected |

### Focus Management

- All interactive elements have `focus-visible:ring-2 focus-visible:ring-cyan-300 focus-visible:ring-offset-2 focus-visible:ring-offset-slate-950` for visible focus indicators.
- Radio groups use roving `tabIndex` so only the checked item is in the tab order.

## Responsive Behavior

- The component uses `flex-wrap` for all button groups, allowing them to wrap naturally on narrow viewports.
- The `PanelShell` wrapper uses responsive padding: `p-4 sm:p-5 xl:p-6`.
- Weekday chips, frequency chips, and end condition chips all wrap to multiple rows as needed.

## Edge Cases Handled

- **DST**: The `rrule` library handles daylight saving time transitions correctly.
- **Month-end (Jan 31 → Feb)**: `rrule` auto-clamps invalid dates.
- **Empty weekday selection**: Shows validation message "Select at least one day" with `role="alert"`.
- **Interval < 1**: Clamped to minimum 1 on blur.
- **No preview available**: Shows "No occurrences to preview." when the rule produces no future dates.

## Dependencies

- `rrule` (^2.8): JavaScript RRULE implementation. Provides `RRule` class, `Weekday` type, and `toText()` for human-readable summaries.

## Anti-Scope (What This Component Does NOT Do)

- No backend API integration or persistence
- No drag-and-drop or calendar grid
- No time-of-day selection (day-level recurrence only)
- No multi-RRULE support (one rule at a time)
- No URL-synced state
- No animations
